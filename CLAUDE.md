## Architecture

- `trello_cli/config.py` — credentials, local-backend root, and hosted-server location (`server_url`/`server_token`, saved by `configure-http`), stored in `~/.trello-cli.json`. Board and backend *selection* are per-invocation only (flags/env), never persisted (see Statelessness)
- `trello_cli/api.py` — thin **facade**; each operation forwards to the active backend via `get_backend()`. `main.py`'s `api.<op>(...)` call sites stay unchanged
- `trello_cli/backends/` — pluggable data sources behind a common interface:
  - `base.py` — the `Backend` ABC: the ~40 operations the CLI needs, all returning Trello-shaped dicts. **`search_cards(board_id, query, *, list_id, include_closed, partial, substring)`** backs `trello search` — an ABC method rather than a client-side filter because each backend answers it natively (Trello forwards to its own index; local scans its own files)
  - `trello.py` — `TrelloBackend`, the httpx client over the Trello REST API (requests only the fields each command needs). Trello has no atomic move-and-return, so `grab_top_card` **fakes** the claim handshake (CONTRIBUTING.md style): grab the top card, post a `I am doing this now — claim <id>` comment, wait a randomized 10-30s, then let the *earliest* in-window claim win — rollback (retract the comment + return the card to the source list) happens only for failures/interrupts *before* adjudication; after it, a loss just retracts its own comment and retries the next card (the winner owns the card) and a win is never undone (`_won_claim`/`_parse_dt` + the `_GRAB_*` tunables; the algorithm mirrors CONTRIBUTING.md's known-good handshake but is **not** verified against live Trello). **`search_cards`** forwards to native `GET /1/search` with the query **verbatim**, so Trello's own operators work as documented and are never reimplemented here; `list_id`/`include_closed` are applied as *post-filters* because probing showed `is:archived` returning open cards (`cards_limit` is raised to `_SEARCH_LIMIT` — the API's own default of 10 turns "find my card" into a silent miss). It **refuses** `--substring` / the per-term `substring:`/`partial:`/`word:` operators (`_GRANULARITY_OP_RE`) rather than degrading to a word match, since a plausible-looking wrong result is the worst thing to hand an agent. **The winner's claim comment is never retracted** - deleting it would let a competitor still inside its own wait see no earlier claim and declare a second win - so it lingers on the card forever, and two things stop a later reader mistaking it for someone else's hold: the win path tags the returned card with the transient key **`claimId`** (the id it posted; `cmd_grab` prints it as `Claim: <id>`), and `_claim_text` appends a self-describing paragraph after the id saying it is `grab` bookkeeping, that the real claim is the card sitting in the in-progress list, and that a claim older than `_GRAB_CLAIM_WINDOW` settles nothing. `_CLAIM_MARKER` + the id are the adjudication key and must stay byte-identical (`_parse_claim` = marker prefix + FIRST whitespace token), so anything appended **after** the id is free and old/new builds interoperate both ways
  - `local.py` — `LocalBackend`, a self-hosted file store. Backs **every** CLI command: boards/lists/cards (CRUD + move/pos/archive/rename/desc/due), labels, checklists, comments, attachments, members, `card mine`, and `activity`/`updates` read from the log. **`update_board`** (a mutator on the ABC, backing `board rename`/`board archive`/`board restore` + the web `PATCH /api/boards/{id}`) renames and/or sets the board's `closed` flag — archiving is a **soft delete**: the board drops out of `get_boards()` (which now takes `include_closed=False`; pass `True` for the archived/recycling-bin view) but its files stay on disk, so `restore` (`closed:false`) brings it back intact; the irreversible folder wipe is still `delete_board`. Labels are stored on cards as `idLabels` and resolved to full dicts from `labels.json` at read time (so `label edit`/`delete` reflect everywhere); comments/checklists/attachments live inline in the card JSON; members are a single OS-username user, so `mine` returns every open card. **Atomic `grab_top_card`** (backing `trello grab`): a mutator that, under the store lock, pops the top open card of a source list and moves it to a dest list in one read-modify-write — so concurrent grabbers each get a *distinct* card with no claim dance (the local native answer to the race CONTRIBUTING.md's handshake works around; same-machine only, Dropbox cross-machine is out of scope). **Persisted per-list `sort`** (the web auto-sort feature, `LIST_SORTS` = `manual`/`created-newest`/`created-oldest`/`activity-newest`/`activity-oldest`/`name`, default `manual`): stored as an optional `sort` key on each `lists.json` entry — written by `create_list`/`create_board`/`import_board`, normalized in `get_lists` (via `normalize_sort`, so a pre-`sort` store never KeyErrors and an unrecognized value degrades to `manual` instead of crashing a read), validated + persisted in `update_list(sort=…)` (which also one-shot re-sorts the list's existing cards). The pre-split spellings `newest`/`oldest` stay accepted forever as aliases of the `activity-*` pair (`_SORT_ALIASES`) and are persisted canonically, so old stores and old clients keep working with no migration. **Every card ARRIVING in a sorted list is auto-placed** into its slot by `_place_in_sorted_list`/`_auto_place_pos`: created there (`create_card`), moved in, or unarchived (both in `update_card`). An **explicit `pos` wins** — the web drag sends `{idList, pos}` and must land where the user dropped it, clearing the column's sort straight after — so `update_card` auto-places only when the call touched placement and named no `pos`. `dateLastActivity` is stamped *before* placement, or an `activity-*` sort would order the arriving card on its stale timestamp. **Creation time** is `dateCreated`, stamped by `_new_card` and resolved once at import by `_card_shape`; the module-level `card_created(card)` is the read accessor and backfills a pre-field card best-effort — decoding the creation time a **Trello** id encodes (gated on `shortLink`/`shortUrl`, which a locally-created card never has, since `new_id()` is random and would decode to a plausible but meaningless date; plus a sanity window), else falling back to `dateLastActivity`. `main._fork_snapshot` stamps `dateCreated` **before** it remints ids, since a fork keeps the source's stale `shortLink` but not its id. Trello has no native per-list sort, so it's **local-only** — the Trello backend drops a `sort` field from `update_list` (clean no-op). Also `import_board(...)` — local-only (not on the ABC), the target of `trello export`: writes a source backend's Trello-shaped board/lists/labels/cards into the store, preserving ids and pruning cards deleted upstream (plus their attachment blob dirs). Two more local-only methods back maintenance: `gc(...)` (the `local gc` sweep: orphaned attachment dirs/files, optional `activity.log` trim) and `delete_board(...)` (the `local rm` board-folder delete), both report-then-delete so the command can offer a dry run. **`search_cards`** (a lock-free read) *mirrors* Trello's native search rather than inventing its own semantics — one command must not mean two things depending on `--backend`. Matches over **name, desc, comments and checklist item names** (it scans the RAW stored card, before `_enrich_card` strips comments); whole-word by default, word-prefix under `partial`, mid-word under `substring`; terms AND, `-term` negates. Trello's operators are implemented where the store holds the data (`name:`/`description:`/`comment:`/`checklist:` scope a term; `list:`/`label:`/`is:`/`has:`/`due:`/`edited:` filter; `sort:` orders), plus the **local-only** per-term granularity operators `word:`/`partial:`/`substring:`. The operator table at the top of the module is the authority on what's deliberately **unsupported** (`created:`/`sort:created` — the store records no creation time, since `new_id()` is random while imported Trello ids encode one, so it'd work on some cards and not others; `has:cover`/`has:stickers`; `member:`; `board:`) — **an unknown operator degrades to literal text, never an error**, and `main._TRELLO_ONLY_OPS` mirrors that list for its hint (a test asserts they agree). Hits carry a transient **`_match`** key (field + matching line) for the CLI's `Matches:` block — set after the read, never persisted, same pattern as `rebalanced`. **Every mutator runs under the store lock** — the `_MUTATORS` tuple at the bottom of the module is the authoritative list of writers (including `update_board`/`grab_top_card`/`gc`/`delete_board`), each wrapped once via `_locked`; reads stay lock-free
  - `store.py` — file-store primitives for `LocalBackend`: 24-hex id gen, atomic JSON/text writes (temp + `os.replace`, with `retry_on_lock`/`is_transient_lock` retrying the brief sharing violations a Dropbox/OneDrive sync or antivirus causes — see Concurrency), float `pos` midpoint math (step 65536), the `needs_rebalance`/`even_positions` collapse-guard (float midpoints can only be halved ~50× before two positions become the same float — `LocalBackend` respreads a list to even spacing once any gap drops below `MIN_GAP`, on every card/list create + pos-update; when a respread fires on a `pos`/move update, `update_card`/`update_list` tag the **returned** dict with a transient `rebalanced: true` — set after the atomic save so it is never persisted, consumed only by the web client to trigger a full reload of the now-stale siblings, ignored by the CLI), append-only `activity.log` (JSONL; written, read, and `tail_activity`-trimmed for retention), the `StoreLock` (cross-process advisory lock, see Concurrency below), and the on-disk layout (`<root>/<boardId>/{board.json, lists.json, labels.json, cards/<id>.json, attachments/<cardId>/…, activity.log}` + a top-level `<root>/.lock`)
  - `http.py` — `HttpBackend`, the CLI on a **hosted trellno server** (`trello serve` running remotely — see `deploy/`): implements the full ABC over the web API, so every command works from any machine that can reach the server, with the server's store as the single source of truth. Nearly every op rides `POST /api/rpc` (the ABC serialized as `{op, args, kwargs}` — mechanical, can't drift); the two client-file ops are the exception (`add_attachment_file` → the multipart upload route, reading the created attachment from the response's transient `_attachment` key; `download_attachment` → `GET /api/blob` for store-relative urls, direct fetch for external ones). Non-2xx responses become `SystemExit(detail)` so remote errors read like native CLI errors (and `_resolve_*`'s "not found" matching keeps working); auth is `Authorization: Bearer` from `configure-http`/`TRELLO_SERVER_TOKEN`. **`grab` over http is truly atomic cross-machine** — the claim runs under the *server's* store lock
  - `__init__.py` — `get_backend()` factory (cached singleton); selects `trello` (default), `local`, or `http` from `--backend` / `TRELLO_BACKEND` (see DESIGN.md)
- `trello_cli/fmt.py` — compact table/detail formatting and small helpers (`short_id`, `truncate`, `due_str`, `label_str`, `is_image`, `size_str`, `print_json`); backend-agnostic (formats plain dicts). `print_card_detail` takes an optional `link=` (the card's magnet, built by the caller so the formatter stays backend-agnostic) and **omits** the `URL:` line when `shortUrl` is absent instead of printing it empty
- `trello_cli/magnet.py` — **magnet links**, the self-contained token that addresses a card or board: `build_card`/`build_board`/`parse`/`is_magnet`/`slugify`. Grammar is path segments, no query string (`trello://card/<backend>/<boardId>/<cardId>[#<slug>]`, plus a percent-encoded `<server>` segment after `http`) — **deliberately not `?board=…&backend=…`**, because a magnet's job is surviving a copy-paste into a shell command and `&` backgrounds an unquoted one while `?` globs; a token silently truncated at `&` is the plausible-looking-wrong-result this repo refuses elsewhere. The trailing `#<slug>` is built from the entity's name and **ignored on parse** (so a renamed card carries a stale slug and still resolves) — 48 chars of hex say nothing about *which* card this is, and being readable in a PR body or a prompt is the token's second job; `#` opens a shell comment only at the start of a word, so it stays one argument unquoted. Ids are emitted full (24 hex) by default, abbreviated by `--short`, and parsed leniently (4-24 hex) — parsed ids go to the existing `_resolve_*` resolvers rather than inventing a second notion of "id prefix". **The http server *token* is never in a magnet** (these strings get pasted into prompts and PR bodies); the server *URL* is. A malformed token is a loud `SystemExit` with the grammar, **the deliberate opposite of `search`'s "unknown operator degrades to literal text"** — a magnet is machine-generated, so anything unparseable means a version mismatch or a hand-edit. Imports nothing from `main`/`api`/`config`, so it unit-tests in isolation
- `trello_cli/main.py` — CLI entry point, noun-group dispatch (`card`, `list`, `label`, `checklist`, `comment`, `attachment`), name/ID prefix resolution. **Board management** (`cmd_board`): besides `board`/`board add`, the verbs `board rename <name>`, `board archive` (soft delete), and `board restore`/`board unarchive` forward to `api.update_board` on the `--board` board; `boards --archived` lists only archived boards and `boards --all` lists both with a State column (default `boards` stays open-only); `boards [<query>]` takes an optional positional filter — **substring** on the name or prefix on the id (client-side on every backend, so unlike card search there's no remote index to mirror), composing with `--archived`/`--all`. **Find** (`cmd_search`, registered as both `search` and `find`): `trello search <query> [--list <list>] [--all] [--partial] [--substring]` calls `api.search_cards` and renders the board-wide `card ls` table plus a `Matches:` block showing the line that matched for desc/comment/checklist hits (a hit is an unexplained row otherwise). Hints are **gated on what the query actually used** — a Trello-only operator on the local backend, or `--substring` advertised when a local search finds nothing — because the CLI surface is the only documentation an agent reads; they go to stderr under `--json` (the split `card ls` uses for its truncation notice). `search --help` is handled explicitly so it isn't answered with "Unknown flag: --help". **Magnet links** (`_card_link`/`_board_link`/`cmd_open`, registered as `card link`, `board link` and the top-level `open`): `card link <card> [--as uri|cmd] [--short]` prints the token as one bare line (so `$(trello card link X)` is usable directly), `--as cmd` prints a ready-to-run command line instead (agents run commands, not URIs — but the URI stays the default because only it round-trips back into structured form), and `card show` prints a `Link:` line, which is the discovery path *and* fills the hole where a local card's `URL:` was always empty. Consuming is the reason the feature exists: a magnet is accepted **anywhere a card ref is** (`trello card comment <magnet> "done"` with no flags at all), which works because `main()` pre-scans raw argv for a `trello://` token *before* the flags are stripped (so a magnet used as a flag *value* is seen too) and seeds the board/backend/server overrides via `_apply_magnet`. **`_find_magnet` stops at the first token that is neither a flag, a flag's value, nor a command/verb word** — that token is the *reference position*, and free text is always a later positional. Taking the first magnet anywhere in argv instead let one quoted in a comment body or card name hijack the invocation (`comment add <id> "done, see trello://card/http/…"` seeded the backend and board from the comment text), and quoting a magnet back at the CLI is exactly what agents will do; `_resolve_card`/`_resolve_board_ref` then unwrap the id and **fall through to ordinary resolution**, so a stale magnet still gets the good "Card not found on this board" rather than a blind cross-board write. **Conflict precedence is split by how deliberate the setting is**: the magnet silently beats the *env* (`TRELLO_BOARD`/`TRELLO_BACKEND`/`TRELLO_SERVER` are ambient defaults, and an agent with `TRELLO_BOARD` exported must be able to paste a magnet and have it work), while an explicit *flag* that disagrees is a hard error naming both values (double-specifying is a real agent habit, and resolving a card id against the wrong backend is the worst outcome available). Agreement is silent and prefix-either-way (`--board <8-char id>` matches a full-id magnet and vice versa); a board *name* alongside a magnet is refused, since comparing it would mean resolving it and a resolve could pick a third board. A **card** magnet passed to `--board` is refused rather than quietly yielding its board, because the same token in `TRELLO_BOARD` is refused by `_resolve_board_ref` and the two channels must not disagree. `_resolve_board_ref` now lists with `include_closed=True` so an archived board can still be addressed (e.g. to restore it). Top-level workflow command `grab` (`cmd_grab`): `trello grab [--from "To Do"] [--to "Doing"]` claims the top card of one list and moves it to another via `api.grab_top_card`, printing the card it got (or the full dict under `--json`) and exiting 1 when there's nothing to grab - plus a `Claim: <id>` line when the backend supplies the transient `claimId` (Trello only; the local backend claims under the store lock and posts no comment, so the key is **absent** there rather than null) — the one-command form of CONTRIBUTING.md's claim handshake, for telling several agents to "grab the top ticket" without them colliding. The `export` command bridges two backends in one invocation — it reads a board snapshot via the `api` facade (shared `_gather_board` helper) and writes via a directly-instantiated *other* backend, bypassing the `get_backend()` singleton — and runs in two directions on `--to`:
  - `--to local` (default, `_export_to_local`): pull from the selected backend (must not be local) into a `LocalBackend`. Also downloads uploaded attachment blobs (default on; `--no-attachments` skips) via the *source* backend's authed `download_attachment`, rewriting each card's attachment url root-relative *before* `import_board` persists it — best-effort (per-blob failure warns + keeps the remote url; immutable blobs are reused on re-export). IDs preserved → idempotent in-place refresh. **`--fork`** flips that: the snapshot lands under a fresh `new_id()` (passed to `import_board(..., board_id=…)`), so the copy is a board in its own right rather than the source's mirror — the **create-new-each-time** contract `--to trello` already has (permanently orphaned: no later export finds it, forking twice makes two boards), for splitting a cloud board into two that diverge. **`_fork_snapshot` remints EVERY id** (lists, labels, cards, comments, checklists+items, attachments) and rewrites the cross-references (`idList`, `idLabels`, `idCard`, `idChecklist`), not just the board's — mandatory, not tidiness: `LocalBackend` resolves entities by scanning *every* board and taking the first hit (`_locate_card`/`_locate_list`/`_locate_comment`/`_locate_checklist`), so ids must stay unique store-wide or a fork + a mirror of one source route every id-addressed write to whichever board id sorts first, silently ignoring `--board` (and passing `_resolve_card`'s cross-board guard on the way). It runs **before** the attachment step, since blob dirs are keyed by card id and blob filenames by attachment id. Cards keep the source's Trello `shortUrl`/`shortLink` — stale deep links, documented not fixed. `--name` is accepted **only** with `--fork` (on a mirror the next re-export would overwrite it) and both directions route it through `_free_text` via `_export_name`, validated up front before any network work. **Ordering is load-critical, not incidental**: the board id is a path component (`<root>/<bid>/attachments/<cardId>/`), so `dest_id` is minted in `_export_to_local` and threaded through *both* attachment helpers before `import_board` — minting inside `import_board` would strand every blob under the source id, and `_preserve_local_attachment_urls(source_id, …)` would seed the fork's cards with urls into the source board's blob dir. A fork also passes `fetch_relative=True` to `_export_attachment_blobs`, re-downloading attachments whose url is *already* store-relative (an http source serves them from its own store); the skip that's right for a mirror (source id == dest id, blob already in place) is a cross-link for a fork. `--to trello` **refuses** `--fork` rather than no-op'ing it, since that direction is already create-new
  - `--to trello` (`_export_to_trello` → `_push_board_to_trello`): push the local store (source backend must be `local`) **up to Trello as a brand-new board**. Trello mints fresh ids, so ids can't be preserved — it builds old→new maps for labels/lists, then re-creates each card and its children (comments, checklists+items, attachments) under the new ids via the ABC's write ops. **Create-new-each-time** (non-idempotent; no local→trello map persisted — keeps statelessness). Re-uploads local blobs (`add_attachment_file`), re-links URL attachments; comments are re-posted as the token user with an `_originally <author>, <date>_` provenance prefix (Trello can't set author/date); `idMembers` dropped; only open lists pushed (`--name` overrides the new board name). A tracked-mapping re-sync (`--into <board>`) is **designed but not implemented** — DESIGN.md works through the id-map sidecar, the diff/reconcile algorithm, and conflict handling, and recommends deferring the build pending a user decision on the conflict policy (it can't be verified against live Trello here)
- `trello_cli/web/` — optional web app (the `[web]` extra: fastapi, uvicorn, watchdog, python-multipart — the last for browser file uploads), launched by `trello serve`:
  - `server.py` — FastAPI JSON API mapping 1:1 onto the `api` facade, so it renders **either** backend with no per-backend code. Endpoints: `GET /api/boards` (`?include_closed=true` adds archived boards for the manage-boards panel), `GET /api/boards/{id}` (board+lists+cards), `PATCH /api/boards/{id}` (rename `name` / archive-restore `closed`), `DELETE /api/boards/{id}?confirm=true` (permanent purge — `confirm=true` required, the web echo of `local rm --yes`; local-only via the facade guard), `POST /api/boards/{id}/lists` (add column), `GET /api/boards/{id}/labels` + `POST /api/boards/{id}/labels` (list/create board labels), `GET /api/cards/{id}` (detail+comments), `PATCH /api/cards/{id}` (drag move/reorder **and** detail-panel edits — title/desc/due/dueComplete), `DELETE /api/cards/{id}` (soft delete = archive), `POST /api/cards/{id}/comments` (add comment), `POST /api/cards/{id}/labels` + `DELETE /api/cards/{id}/labels/{labelId}` (add/remove a label, returns the fresh card), `POST /api/cards/{id}/attachments` (add a URL attachment) + `POST /api/cards/{id}/attachments/file` (multipart upload — saves to a temp file then `add_attachment_file`) + `GET /api/cards/{id}/attachments/{attId}/raw` (serve an **uploaded** blob's bytes — a local blob, or a Trello-hosted upload fetched with OAuth — streamed via `download_attachment` into a temp file and returned inline; external URL attachments are **not** proxied, the browser links them directly, so the server never fetches an arbitrary URL) + `DELETE /api/cards/{id}/attachments/{attId}` (remove); the add/delete routes all return the fresh card, `PATCH /api/lists/{id}` (column reorder `pos`, archive `closed`, persisted `sort`), `POST /api/lists/{id}/cards` (create), `GET /api/events?board=<id>` (SSE live-refresh stream; the `?board=` lets the Trello backend poll that board). Two extra routes exist for the **http backend**, not the browser: `POST /api/rpc` (dispatches a whitelisted Backend-ABC op — `_RPC_OPS`, derived from the ABC minus the two file ops; local-only maintenance ops are excluded — to the facade, returning `{"result": …}`) and `GET /api/blob?url=<store-relative>` (streams an uploaded blob by its stored url; absolute urls are refused, so it can't be steered into SSRF), and the multipart upload route returns the created attachment under a transient `_attachment` key alongside the fresh card. Backend `SystemExit` (not-found) is translated to HTTP 404; the PATCH whitelists are enforced by `_guard` (`_CARD_PATCH_FIELDS` = `idList,pos,name,desc,due,dueComplete`; `_LIST_PATCH_FIELDS` = `pos,closed,sort`; `_BOARD_PATCH_FIELDS` = `name,closed`). **Auth:** loopback binds are open; a non-loopback `serve --host` is token-gated — `serve(token=…)` (auto-minted if absent) installs middleware that requires the token (`Authorization: Bearer` **or** `?token=` — the query param is the only channel a browser nav / `EventSource` has) on `/api/*` only, leaving the static shell public so `app.js` can load and then attach the token itself. For a hosted deployment (loopback bind behind a TLS reverse proxy) `serve --allow-host <domain>` admits the proxied public domain through the Host-header (DNS-rebinding) guard — systemd unit + Caddyfile + full runbook in `deploy/`
  - `live.py` — live-refresh plumbing: a `watchdog` observer on the local store root bumps a monotonic version counter; the `GET /api/events` async generator polls it and emits `event: change` (a counter polled across the thread boundary, no event-loop hand-off). The watchdog is local-backend only; the Trello backend has no local files, so the `/api/events` stream instead polls the viewed board's latest action id (via `?board=<id>`) every 5s (`poll_every`) and emits `change` when it advances, surfacing edits from other CLIs or the Trello web app; without a board it stays keep-alive only
  - `static/` — vanilla JS + SortableJS (vendored under `static/vendor/`, no build step): columns + cards (a card face shows a `📎 N` badge when it has attachments — instant on the local backend, whose `get_board_cards` carries them inline; on the Trello backend, whose board-cards request stays field-narrowed, the badge appears once the card is opened), drag-drop reorder/move computing the float `pos` midpoint client-side, an **editable** card detail panel (Trello-style: click-to-edit title + description via `inlineEditable`, label popover that picks existing board labels and creates new ones on the fly, due-date popover with a native date picker + complete toggle, an **attachments** section (image thumbnails / file+link rows with size, each linking to the blob — uploads via the token-gated `/raw` proxy, external links direct — plus a delete ×, and a "📎 Attach" popover to upload a file or paste a URL; mutations go through `renderDetailAttachments`/`applyCardUpdate` like labels/due), add-comment composer, and a delete control behind a confirm). **Bare `http(s)://` URLs in the description, comment bodies and checklist item names render as real links** (new tab, `rel=noopener noreferrer`) via **`linkify(text)`**, which returns a DocumentFragment of alternating **text nodes + `<a>` elements**: never `innerHTML`, so the non-URL text stays escaped **by construction**, keeping the exact safety property of the `textContent` it replaced (card text is user-authored and syncs between machines on the local backend, so a stored-XSS hole here would be a real one). Matching is `http`/`https` only, so `javascript:`/`data:` cannot be smuggled into an href; `trimUrlTail` walks trailing sentence punctuation back out of the match but keeps a closing bracket the URL itself opened (`.../Foo_(bar)` stays whole, `(see https://x/a)` does not eat the paren), and a match trimmed down to a bare scheme (prose like "must start with https://.") stays plain text instead of becoming an underlined link to nowhere. `tests/test_linkify.py` runs these cases through the real `app.js` source under `node` against a minimal DOM shim (auto-skipped when `node` is not on PATH), so the punctuation/bracket rules have a regression guard despite there being no JS test runner in the repo. **Card titles are deliberately NOT linkified** in either render: on the board face because it is a SortableJS drag handle and an anchor there would fight it for the mousedown, and in the detail panel `<h2>` for consistency with it (a title is a one-line label, so a link in one is noise rather than the reference a description or comment carries). `inlineEditable`'s read view ignores a click that lands inside an `<a>`, so clicking a link in the description opens it instead of dropping the box into edit mode. Markdown rendering is explicitly out of scope (it would need a vendored parser + sanitizer). The board also runs an `EventSource` on `/api/events?board=<id>` that reloads the board on a `change` event (skipped mid-drag) and reconnects with the new id when the picker changes. The selected board is persisted in the URL (`?board=<id>`, alongside `?token=`) and restored on reload/bookmark (fixing the F5-snaps-back-to-first-board bug), falling back to the first board if absent or invalid. **Board quick-swap bar:** the topbar renders a `#board-nav` of one-click buttons for **starred** boards (the active one highlighted with the accent), with the `#board-picker` dropdown holding only the *non-starred* boards (moved top-right, hidden when empty) and a ★/☆ `#star-toggle` for the current board just before it. Stars are a **client-side preference** — a JSON array of board ids in `localStorage` (key `trellno:starredBoards`), so starring stays web-only with **zero backend/dict-contract change** (board *renaming*/*archiving* is a separate, server-backed feature — see Manage-boards panel below). `renderNav()` rebuilds the bar from `allBoards` + the starred set + `currentBoardId` (pure DOM, no fetch — cheap after a star toggle); `selectBoard(id)` drives every board switch (URL + `renderNav` + `loadBoard` + `initLive`), replacing the old `picker.value` as the source of truth for the current board. Buttons squish (ellipsis, `max-width`) before they overflow the bar. **A re-render never costs the user their place or their typing:** `renderBoard` wipes `boardEl` and rebuilds, and reloads are not all user-initiated (a live change, or another agent's CLI write, can land mid-sentence), so `captureBoardState`/`restoreBoardState` carry the per-column composer text + focus + caret, the open "Add another list" composer, and the board's horizontal / per-column vertical scroll across the rebuild. Live `change` events are **debounced** (`LIVE_DEBOUNCE_MS`) so a burst of store writes — a column re-sort rewrites every card file in it, and a sync client replays those writes — collapses into one reload, and refreshes nobody asked for run **quiet** (`loadBoard(id, {quiet: true})`: no "Loading…" status churn, and the render is skipped entirely when the fetched payload matches `lastBoardSig`, i.e. the board would be drawn exactly as it already is). That payload compare is what keeps a self-caused live event from re-rendering — cheaper than trying to work out *whose* change it was, and never wrong. After a detail-panel mutation the open card + its board face are patched in place (`applyCardUpdate`/`refreshCardFace`/`removeCardFace`) so the change shows before the SSE reload lands. A drop also reloads the board immediately when its move/reorder PATCH response carries `rebalanced: true` (see the collapse-guard note under `store.py`/`local.py`) — without it only the dragged element's `data-pos` updates and the respread siblings stay stale until the SSE reload. **Column management:** an "Add another list" affordance after the last column (`addListEl`, `POST /api/boards/{id}/lists`), a per-column `⋯` actions menu holding a **Sort by** section (Manual / Newest / Oldest first **(created)** / Newest / Oldest first **(updated)** / Card name, persisted via `PATCH {sort}`; current choice marked `.active` — the server reports a pre-split store's `newest`/`oldest` in its canonical `activity-*` spelling, so the menu never has to know the alias table) and **Delete list** (archive via `PATCH {closed:true}`). A manual card drag onto an auto-sorted column **clears that column's saved sort** back to `manual` (so the user's hand-placement isn't immediately overridden) — done web-side in the card `onEnd`. **Manage-boards panel:** a topbar `⚙` button (`#manage-boards-btn`) opens `openManageBoards`, which reuses the detail drawer + overlay as a generic right-side panel (no routing) and fetches `GET /api/boards?include_closed=true`, splitting on `closed`: an **Active boards** section (each row = click-to-rename via `inlineEditable` + an **Archive** button → `PATCH {closed:true}`) and an **Archived** section — the recycling bin — (each row = **Restore** → `PATCH {closed:false}` and a confirm-gated **Delete** → `DELETE /api/boards/{id}`, the permanent purge). After any board mutation, `reloadBoardsNav()` re-fetches the open boards and re-skins the nav; if the **current** board was archived/purged it switches to the first remaining open board, then `renderManagePanel()` rebuilds the panel
- `ax/` — **AX (agent-experience) harness**, the second verification gate: `tests/` asks "is the code right?", `ax/` asks "can a model that has never seen this repo drive the CLI from `--help` and error messages alone?" — the question that matters because every caller here is an agent. `fixture.py` seeds a throwaway store per run; `cases.py` is the corpus (tiers 1–3, each with a plain-English `prompt` that avoids the CLI's own vocabulary, a `budget` = healthy median tool-call count, and a `verify` that reads the **store** back — plus optional `expect`/`forbid` on the answer, `readonly` (fails if the store changed at all), and `expect_cmd` (a regex the commands must match, for tasks where the right outcome reached the wrong way is still a failure — e.g. `grab`)); `runner.py` fans the corpus out across cold `claude -p` runs (`--tools Bash`, a PATH holding only a `trello` shim, `--setting-sources ""`/`--strict-mcp-config`/`--disable-slash-commands` so no CLAUDE.md, hook, MCP server or skill leaks in, and **no** `TRELLO_BOARD`, since forgetting `--board` is the commonest agent mistake), retrying provider 429/529s (which carry no AX signal) and merging a re-run subset over an existing `results.json`; `render.py` squeezes each stream-json log into a ~50–100× smaller transcript (first command, errors, retries, final answer); `report.py` writes `index.md` (scoreboard + error classes + failing transcripts inlined, built to paste into a model) and `corpus.md`; `compare.py` diffs two runs on calls/errors/budget, re-scoring both under current case rules. Findings and the fixes they produced live in `ax/FINDINGS.md`; `tests/test_ax_affordances.py` locks those fixes in so an ergonomic regression trips the unit suite

## Conventions

- **Noun-group dispatch** — `_dispatch(group, subcmds, args)` routes verbs within a group. Bare nouns (or nouns followed by a non-verb) fall back to `ls` if the group has one, so `trello list` ≡ `trello list ls`.
- **Resolvers** — every domain has a `_resolve_*` helper that accepts an ID, an ID prefix, or a case-insensitive name prefix, and raises `SystemExit` on miss/ambiguity.
- **Invented flags never become data** — agents guess `--card`/`--name`/`--text` because every other CLI has them, so a `--`-prefixed token is refused wherever a *value* belongs, not silently stored. Three guards cover the three shapes: `_parse_flags` (commands with flags), `_reject_flag_value` (the `_resolve_*` helpers), and `_free_text` (**names, descriptions and comment bodies** — the sink no resolver sees, where `label add --card X --label Y` used to create a label named `--card X --label Y` and exit 0). A bare `--` ends flag parsing in all of them, so a value that really does start with dashes stays reachable. **Adding a command that joins free text into a value? Route it through `_free_text`.**
- **Magnet links are a card ref, not a command** — `trello://…` is accepted wherever a card id or board ref is, and it supplies the board/backend/server itself. **Adding a command that takes a card or board reference? Route it through `_resolve_card` / `_resolve_board_ref`** (as everything already does) and it accepts magnets for free; anything that pattern-matches an id itself would silently not. The token is *not* stored anywhere — it is parsed into the same per-invocation overrides `--board`/`--backend` set, so Statelessness holds.
- **Board scope** — `_require_board()` resolves the board from `--board <name_or_id>` (parsed in `main()`) or the `TRELLO_BOARD` env var, and errors if neither is set. There is no stored "active board" (see Statelessness).
- **Backend scope** — `get_backend_name()` selects the data source from `--backend <trello|local|http>` (parsed in `main()`) or the `TRELLO_BACKEND` env var, defaulting to `trello`. The local store folder resolves as `--local-root` flag > `TRELLO_LOCAL_ROOT` env > config `local_root` > `~/Dropbox/trello-cli`; `trello local init [path]` creates it and persists `local_root`. The http backend's server resolves as `--server` flag > `TRELLO_SERVER` env > config `server_url` (token: `TRELLO_SERVER_TOKEN` env > config `server_token`); `trello configure-http <url> [<token>]` persists both.
- **Statelessness (design guideline)** — the CLI is used by many agents and projects concurrently, so it keeps **no shared mutable session state**. Selection (board, backend) is always per-invocation via flags/env; only stable config (credentials, `local_root`) is persisted. Don't add "active X" state — that creates cross-invocation conflicts. (The legacy active-board feature was removed for exactly this reason; everything uses `--board`.)
- **Output mode** — `--json` is stripped in `main()` and toggles `_JSON_MODE`; read commands branch on `_is_json()` to emit raw JSON via `print_json` instead of formatted tables.
- **Backend seam** — commands never touch a concrete backend or transport. They call `api.<op>(...)`, which forwards to `get_backend()`. Every backend returns the same Trello-shaped dicts (the keys `fmt.py` reads), so adding a backend means implementing the `Backend` ABC — no command or formatter changes.
- **Concurrency (local backend)** — many agents run the CLI at once, so every `LocalBackend` *write* is a read-modify-write that would otherwise lose updates (and crash on Windows' `os.replace`) when two processes race the same file. `StoreLock` (in `store.py`) serializes them: a cross-process OS advisory lock on `<root>/.lock` (`fcntl.flock` / `msvcrt.locking`, auto-released on process death) plus an in-process `threading.RLock` for re-entrancy + thread-safety, with a bounded blocking wait. It wraps the whole load→modify→save of each mutator (the `_MUTATORS` list). **Adding a new mutating op? Add its method name to `_MUTATORS`.** Reads are intentionally lock-free (atomic writes already give each file a consistent view). **Transient sharing violations** are a separate hazard the store lock cannot help with: a sync client / indexer / antivirus briefly opens a store file, and Windows then fails `os.replace` (WinError 5/32) or the read. Every store read and write therefore retries via `retry_on_lock` (~1.4s budget, bounded because it is spent holding the store lock), and a write that still cannot land raises a clean `SystemExit` stating **nothing was changed** rather than a traceback. This is what makes `grab` safe in practice: an unretried blip used to abort the move with the card still in the source list, so the next agent grabbed the same card while the first misread the traceback as a claim. Scope: same-machine multi-process. Cross-machine Dropbox edits stay last-write-wins (OS locks don't cross machines) — see DESIGN.md.
